Class 1 — Spring Framework Introduction

1 Introduction — What is Spring? (20 min) ▾
"Before Spring, Java developers used Java EE (Enterprise Edition) to build big applications. But Java EE was very heavy, complex and needed lots of configuration. A developer named Rod Johnson in 2003 felt the same problem and he created Spring Framework to make Java development simple and lightweight."
"Think of it like this — if Java EE is like a big heavy truck, Spring Framework is like a car. Both take you to the destination, but the car is easier to drive, cheaper, and more flexible."

Definition

→Spring is a lightweight, open-source framework used to develop enterprise-level Java applications
→Developed by Rod Johnson in 2003
→Based on two main concepts: IoC (Inversion of Control) and DI (Dependency Injection)
→Helps create flexible, modular, and maintainable applications

4 IoC Container — What it is and Why ▾
"Normally in Java, if ClassA needs an object of ClassB, you write: ClassB obj = new ClassB(); This means ClassA is DEPENDENT on ClassB. If ClassB changes, ClassA also has to change. This is called TIGHT COUPLING — it's a problem."
"IoC means — give the control of creating objects to Spring, not to the developer. Spring will create and manage objects for you. This is called LOOSE COUPLING — it's the solution."

Without IoC (Bad way)

// Developer creates the object manually public class ClassA { ClassB obj = new ClassB(); // tight coupling! // if ClassB changes, ClassA breaks }

With IoC (Spring way)

// Spring creates the object and gives it to ClassA public class ClassA { ClassB obj; // Spring will inject this automatically! }

3 Reasons Why IoC is used

1.Loose Coupling — classes don't depend directly on each other
2.Easier Testing — you can replace objects with mock objects for testing
3.Better Code Management — Spring handles the full lifecycle of beans automatically
5 BeanFactory vs ApplicationContext (20 min) ▾
"Spring gives us two containers. Think of a container as a factory that creates and manages objects (beans). There are two types: BeanFactory (basic) and ApplicationContext (advanced). In real projects we always use ApplicationContext."

BeanFactory — Basic Container

BeanFactory factory = new XmlBeanFactory( new FileSystemResource("applicationContext.xml") ); // Beans are created LAZILY (only when requested)

ApplicationContext — Advanced Container

ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml"); // Beans are created EAGERLY (at startup)
