2 What is Dependency Injection? ▾
"First let me a what is a dependency? If ClassA needs ClassB to work, then ClassB is a dependency of ClassA. Now — who creates that ClassB object? Normally YOU create it using new keyword. DI means Spring creates and gives it to you automatically."
Definition — Dependency Injection
Dependency Injection is a feature of Spring where the IoC Container automatically provides (injects) the required objects (dependencies) to a class. The developer does not create objects manually using new keyword. Spring reads the XML configuration and injects everything automatically.

Without DI — The Problem (Tight Coupling)

Without DI — BAD WAY
public class Student { // Developer creates // Address object manually Address addr = new Address(); // Problem: // Student depends directly // on Address class // Tight Coupling! // If Address changes // Student also breaks }
With DI — SPRING WAY
public class Student { // Spring injects Address // object automatically Address addr; // Student does not know // HOW Address is created // Loose Coupling! // Spring handles everything // from outside using XML }

4 Reasons Why We Need DI

1.Loose Coupling — Classes do not depend directly on each other. Easy to change one without breaking another.
2.Easy Object Management — Spring creates and manages all objects. Developer does not worry about creation.
3.Code Reusability — Same bean can be injected into multiple classes. Write once, use anywhere.
4.Easy Testing — You can replace real objects with mock objects for testing without changing code.

How DI Works — Full Flow

1
IoC Container reads XML configuration file or Java annotations
2
Container creates Bean 1 and Bean 2 based on configuration
3
Container INJECTS Bean 2 into Bean 1 automatically — no manual new keyword
4
Container manages lifecycle of all beans — creation, use, and destruction
"So in simple words — YOU define what you need in XML. Spring reads it and gives it to you. That is Dependency Injection."
3 Types of Dependency Injection ▾
"Spring supports 2 main types of Dependency Injection. Today we will code both. Understanding the difference between them is very important for interviews and tests."
Type 1 — Setter Injection
Spring injects dependencies using setter methods

Uses <property> tag in XML

Used when dependencies are optional or can change later

Spring first creates object using default constructor — then calls setters
Type 2 — Constructor Injection
Spring injects dependencies using constructor

Uses <constructor-arg> tag in XML

Used when dependencies are mandatory at object creation

Spring creates object and injects values at the same time
Spring team recommends Constructor Injection as first choice because it makes dependencies immutable and code cleaner. Setter Injection is used when dependencies are optional.
4 Setter Injection ▾
"Setter Injection is what we already did in Class 2 — but we did not know its name. When Spring calls setName() and setAddress() to put values — that is Setter Injection. Let us understand it properly now."
Definition — Setter Injection
In Setter Injection Spring uses the setter methods of a class to inject the dependency values. The bean must have setter methods for each field that needs to be injected. In XML we use the <property> tag. Spring first creates the object using the default no-argument constructor and then calls the setter methods one by one to inject values.

How Setter Injection Works Internally

1
Spring reads: <bean id="s1" class="demo.Student">
2
Spring calls: Student s1 = new Student() — default constructor
3
Spring reads: <property name="name" value="Rahul">
4
Spring calls: s1.setName("Rahul") — setter method
5
Spring reads: <property name="address" value="Pune">
6
Spring calls: s1.setAddress("Pune") — setter method
7
Bean s1 is fully ready with all values injected

Setter Injection — Full Code

src/demo/Student.java
package demo; public class Student { // private fields private String name; private String address; // DEFAULT CONSTRUCTOR — Spring needs this for Setter Injection public Student() { System.out.println("Student Default Constructor called"); } // Setter for name — Spring calls this to inject name public void setName(String name) { this.name = name; } // Setter for address — Spring calls this to inject address public void setAddress(String address) { this.address = address; } // Getter for name public String getName() { return name; } // Getter for address public String getAddress() { return address; } // Display method public void showdetails() { System.out.println("Name = " + name); System.out.println("Address = " + address); } }
src/applicationContext.xml — Setter Injection using <property> tag
<?xml version="1.0" encoding="UTF-8"?> <beans xmlns="http://www.springframework.org/schema/beans" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd"> <!-- Setter Injection — using property tag --> <bean id="s1" class="demo.Student"> <property name="name" value="Rahul" /> <property name="address" value="Pune" /> </bean> <bean id="s2" class="demo.Student"> <property name="name" value="Priya" /> <property name="address" value="Mumbai" /> </bean> </beans>
src/demo/Test.java
package demo; import org.springframework.context.ApplicationContext; import org.springframework.context.support.ClassPathXmlApplicationContext; public class Test { public static void main(String[] args) { ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml"); Student s1 = (Student) context.getBean("s1"); s1.showdetails(); Student s2 = (Student) context.getBean("s2"); s2.showdetails(); } }

Output — Setter Injection

Student Default Constructor called Student Default Constructor called Name = Rahul Address = Pune Name = Priya Address = Mumbai
"Notice — Default Constructor is called first. This proves Spring first creates empty object, then calls setters to inject values. That is Setter Injection."

2 Benefits of Setter Injection

1.Flexible — Dependencies can be changed later even after object is created
2.Optional Dependencies — If a setter is not called object still works with null value
5 Constructor Injection ▾
"Constructor Injection means Spring injects values through the constructor of the class. Instead of calling setters after creating the object, Spring passes all values directly when creating the object itself. It uses constructor-arg tag in XML."
Definition — Constructor Injection
In Constructor Injection Spring injects the dependency values through the constructor of the class. The class must have a parameterized constructor. In XML we use the <constructor-arg> tag. Spring creates the object and injects all values at the same time through the constructor — not through setter methods.

How Constructor Injection Works Internally

1
Spring reads: <bean id="s1" class="demo.Student">
2
Spring reads all <constructor-arg> tags — collects all values
3
Spring calls: Student s1 = new Student("Rahul", "Pune") — parameterized constructor
4
Object is created with all values already injected — no separate setter calls needed

Constructor Injection — Full Code

src/demo/Student.java — with Parameterized Constructor
package demo; public class Student { private String name; private String address; // DEFAULT CONSTRUCTOR public Student() { System.out.println("Default Constructor"); } // PARAMETERIZED CONSTRUCTOR — Spring uses this for Constructor Injection public Student(String name, String address) { this.name = name; this.address = address; System.out.println("Parameterized Constructor called"); } // Getters public String getName() { return name; } public String getAddress() { return address; } // Display method public void showdetails() { System.out.println("Name = " + name); System.out.println("Address = " + address); } }
src/applicationContext.xml — Constructor Injection using <constructor-arg> tag
<?xml version="1.0" encoding="UTF-8"?> <beans xmlns="http://www.springframework.org/schema/beans" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd"> <!-- Constructor Injection — using constructor-arg tag --> <bean id="s1" class="demo.Student"> <constructor-arg value="Rahul" /> <constructor-arg value="Pune" /> </bean> <bean id="s2" class="demo.Student"> <constructor-arg value="Priya" /> <constructor-arg value="Mumbai" /> </bean> </beans>
Order matters in Constructor Injection! The first constructor-arg value goes to first parameter of constructor, second goes to second. Make sure order in XML matches constructor parameter order.
src/demo/Test.java — same as before
package demo; import org.springframework.context.ApplicationContext; import org.springframework.context.support.ClassPathXmlApplicationContext; public class Test { public static void main(String[] args) { ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml"); Student s1 = (Student) context.getBean("s1"); s1.showdetails(); Student s2 = (Student) context.getBean("s2"); s2.showdetails(); } }

Output — Constructor Injection

Parameterized Constructor called Parameterized Constructor called Name = Rahul Address = Pune Name = Priya Address = Mumbai
"Notice — this time Parameterized Constructor is called — NOT default constructor. This proves Spring directly created the object with values already injected. That is Constructor Injection."

2 Benefits of Constructor Injection

1.Immutable dependencies — Once injected through constructor values cannot be changed. Safe and secure.
2.Cleaner code — All required dependencies are guaranteed at object creation time. No null values possible.
6 Setter vs Constructor Injection — Difference Table — 10 min ▾
"This difference table is very important for your test and for interviews. Write this down carefully."
Parameter Setter Injection Constructor Injection
XML Tag used <property> <constructor-arg>
How Spring injects Through setter methods Through constructor
Object creation Default constructor called first, then setters called Parameterized constructor called — values injected at creation
When to use When dependencies are optional or can change later When dependencies are mandatory and must be provided at creation
Dependency type Optional dependencies Mandatory dependencies
Immutability Not immutable — values can be changed after injection Immutable — values cannot be changed after injection
Efficiency Slightly slower — object created first, then values injected Faster — object created with values in one step
Null values Possible — if setter not called field stays null Not possible — constructor ensures all values provided
Recommended? Not recommended as first choice Recommended by Spring team as first choice
Simple rule to remember: Optional things → Setter Injection. Mandatory things → Constructor Injection. Spring team recommends Constructor Injection always.
